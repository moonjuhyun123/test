# 화면별 상세 명세 + 상태 정의

기준 입력: 01_요구사항명세서.md, 07_화면목록.md, 08_디자인_시스템_명세서.md, 09_분할계획.md

사용 컴포넌트는 모두 08에 정의된 것만. 상태 7종(로딩/데이터 있음/빈값/API 에러/권한 없음/입력 검증 실패/성공)을 모든 화면에 적용.

## S001: 로그인

### 컴포넌트 배치
- 중앙 카드(Card, 360px)
  - 상단: 로고 + 제목("캘린더")
  - TextField (label="아이디", type=text, required)
  - TextField (label="비밀번호", type=password, required)
  - Button (primary, fullWidth, label="로그인")
  - 하단: ErrorState 슬롯(인증 실패 메시지)

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 입력 | 아이디/비밀번호 | 로컬 state 갱신 |
| 엔터 | 비밀번호 필드 | 로그인 버튼 submit |
| 클릭 | 로그인 버튼 | `POST /api/auth/login` 호출, 성공 시 JWT 저장 + S101로 이동 |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 버튼 loading, 입력 disabled | Button(loading) |
| 데이터 있음 | 해당 없음 (입력 폼 화면, 데이터 표시 아님) | — |
| 빈값 | 해당 없음 | — |
| API 에러(401) | 필드 아래 "아이디 또는 비밀번호가 일치하지 않습니다" (01 F001 예외/복구) | TextField.error + 카드 하단 inline |
| API 에러(5xx) | "잠시 후 다시 시도해 주세요" + Retry Button | ErrorState |
| 권한 없음 | 해당 없음 (공개 진입점) | — |
| 입력 검증 실패 | 아이디/비밀번호 미입력 시 "필수 입력" | TextField.error |
| 성공 | Toast(success, "로그인되었습니다") + S101 이동 | Toast |

## S002: 메인 셸 (공통 레이아웃)

독립 라우트 아닌 공통 레이아웃. 모든 보호 라우트가 `<Outlet/>`으로 렌더.

### 컴포넌트 배치
- Header (fixed, z-header, h=56px)
  - Left: 로고 + 앱명
  - Center: SearchBar (placeholder="일정·메모 통합 검색")
  - Right: IconButton(Bell, 알림) + Avatar + DropdownMenu
- Sidebar (fixed, z-sidebar, w=240px)
  - Nav 링크 3종: 캘린더(/calendar), 메모(/memos), 태그 관리(/tags)
  - 각 링크: 아이콘 + 라벨 + 선택 상태 표시
- MainContent (padding 24px): `<Outlet/>`
- Portal root: ToastContainer, ModalRoot (전역)

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 클릭 | 로고 | S101(캘린더 월)로 이동 |
| 입력 + 엔터 | SearchBar | S003(`/search?q=...`)으로 이동 |
| 클릭 | Bell IconButton | S401 알림 패널 열기(팝오버) |
| 클릭 | Sidebar 링크 | 해당 화면 이동 |
| 클릭 | Avatar | DropdownMenu 열기 (항목: "로그아웃") |
| 클릭 | DropdownMenu "로그아웃" | JWT 제거 + S001으로 이동 |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 해당 없음 (정적 셸) | — |
| 데이터 있음 | 현재 사용자 이니셜 Avatar | Avatar |
| 빈값 | 해당 없음 | — |
| API 에러 | 해당 없음 (셸 자체는 API 미호출) | — |
| 권한 없음(미인증) | 전 화면 → S001 리다이렉트 (전역 가드) | — |
| 입력 검증 실패 | 해당 없음 | — |
| 성공 | 알림 수신 시 NotificationToast 자동 표시 | Toast |

**로그아웃 귀속**: 02_review/07_review 메모에 따라 별도 화면 없이 S002 DropdownMenu 항목으로 귀속 확정.

## S003: 통합 검색 결과

### 컴포넌트 배치
- 상단: SearchBar (초기값 = URL `q`) + RadioGroup(타입 필터: 전체/일정/메모) + TagPicker(태그 필터)
- 본문: List — 결과 항목 타입별 렌더 (일정 ↔ 메모 혼재)
  - 각 항목: 아이콘(Calendar|NotebookText) + 제목 + 요약(시간·장소 or bodyExcerpt) + 태그 칩
- 하단: Pagination (page/size — 기본 size 20)

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 입력 + 엔터 | SearchBar | URL `q` 갱신 + 재조회 |
| 선택 | RadioGroup(ALL/SCHEDULE/MEMO) | URL `type` 갱신 + 재조회 |
| 선택 | TagPicker | URL `tagIds` 갱신 + 재조회 |
| 클릭 | 일정 결과 | S103(`/schedules/:id`)으로 이동 |
| 클릭 | 메모 결과 | S202(`/memos/:id`)으로 이동 |
| 클릭 | Pagination | URL `page` 갱신 + 재조회 |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 5~10줄 Skeleton | Skeleton |
| 데이터 있음 | 결과 List + 총 건수 + Pagination | List |
| 빈값 | EmptyState("검색 결과가 없습니다", 아이콘 Search) | EmptyState |
| API 에러 | ErrorState("검색 중 오류가 발생했습니다", retry) | ErrorState |
| 권한 없음 | 해당 없음 (본인 데이터 범위 자동 필터) | — |
| 입력 검증 실패 | keyword 없이 제출 시 "검색어를 입력하세요" | TextField.error |
| 성공 | 결과 즉시 갱신 (토스트 없음) | — |

## S103: 일정 상세 · 수정

### 컴포넌트 배치
- 상단 툴바: 뒤로 + 제목 영역(제목 + 반복 Badge) + IconButton(Edit) + IconButton(Trash2)
- 좌측(2/3): 일정 정보
  - 시간 범위("2026-04-20 09:00 ~ 10:00") + 장소 + 반복 규칙 + 알림 분
  - TagPicker (읽기 모드에서는 Tag Chip 나열, 편집 모드에서 선택 가능)
  - FileUploader(읽기 모드에서는 첨부 목록 Card로 표시, 편집 모드에서 추가/삭제)
- 우측(1/3): 붙은 메모 패널
  - Heading "붙은 메모" + Button(secondary, "메모 붙이기")
  - List — MarkdownRenderer로 각 메모 요약 + 연결 해제 IconButton
  - 메모 없음 시 EmptyState("붙은 메모가 없습니다")

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 클릭 | Edit | 화면을 편집 모드로 전환 (동일 라우트, inline 필드 활성화) |

| 취소 | 편집 모드 "취소" 버튼 | 원복 + 읽기 모드 |
| 클릭 | Trash2 | Modal(삭제 확인) |
| 확인 | 삭제 Modal | `DELETE /api/schedules/:id` → S101로 복귀 |
| 클릭 | "메모 붙이기" 버튼 | Dropdown 2선택: "새 메모 작성" → S203(로 이동 + `attachToScheduleId`) / "기존 메모 선택" → S201(선택 모드 + `attachToScheduleId`) |
| 클릭 | 연결 해제 IconButton | 확인 Modal → `DELETE /api/links/:linkId` |
| 클릭 | 붙은 메모 항목 | S202 |
| 입력 | TagPicker (편집 모드) | 로컬 상태 갱신 |
| 업로드 | FileUploader | `POST /api/attachments` (multipart, target=SCHEDULE) |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 헤더 + 좌우 패널 Skeleton | Skeleton |

| 빈값(붙은 메모 없음) | EmptyState("붙은 메모가 없습니다", action=메모 붙이기) | EmptyState |

## S104: 일정 생성

전용 라우트 또는 Modal. 본 명세는 **전용 라우트** 기준 (Modal에 재사용 가능).

### 컴포넌트 배치
- 상단: 뒤로 + 제목 "새 일정"
- 폼 2컬럼
  - TextField "제목" (required, maxLength=200)
  - DateTimePicker "시작" (required) + DateTimePicker "종료" (required)
  - TextField "장소" (optional, maxLength=200)
  - Select "반복" (NONE/DAILY/WEEKLY/MONTHLY, 기본 NONE)
  - NumberInput "시작 전 알림 (분)" (기본 30, 0~1440)
  - TagPicker "태그" (optional, allowCreate)
  - FileUploader "첨부" (optional, target=SCHEDULE, ≤5개, ≤10MB)
- 하단: Button(primary, "저장") + Button(ghost, "취소")

**F005 특수 진입** (S202 → S104): 쿼리스트링 `sourceMemoId=...` 전달 시 저장 후 자동으로 `POST /api/links` (origin=MEMO_TO_SCHEDULE) 호출. UI에는 "이 일정은 '(메모 제목)'에서 생성됩니다" 안내 배너 표시.

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 입력 | 각 필드 | 로컬 state 갱신 + 실시간 유효성 표시 |
| 클릭 | 저장 | `POST /api/schedules` 호출 → 성공 시 S103 이동(또는 S101) |
| 클릭 | 취소 | 뒤로 (브라우저 히스토리) |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 저장 버튼 loading, 폼 disabled | Button(loading) |
| 데이터 있음 | 해당 없음 (생성 폼) | — |
| 빈값 | 초기 빈 폼 | — |
| API 에러 | Toast(error, "저장 실패, 다시 시도해 주세요") + 폼 유지 | Toast |
| 권한 없음 | 해당 없음 (인증 사용자 모두 가능) | — |
