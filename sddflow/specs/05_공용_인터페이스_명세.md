## 인터페이스: ScheduleReader

구현: 일정 모듈. 다른 모듈이 일정 데이터를 **읽기 전용**으로 참조.

### 메서드
| 메서드 | 입력 | 반환 | 설명 |
|--------|------|------|------|
| `findById(Long id)` | 일정 ID | `Optional<ScheduleSummary>` | 단건 조회, 없으면 empty |
| `existsByIdAndOwner(Long id, Long ownerId)` | 일정 ID, 소유자 ID | `boolean` | 첨부·태그·연결에서 소유자 동일성 검증 |
| `findSummariesByIds(List<Long> ids)` | 일정 ID 목록 | `List<ScheduleSummary>` | 검색·알림 배치 조회 |
| `search(ScheduleSearchQuery query)` | 검색 조건 | `List<ScheduleSummary>` | 검색 모듈 전용. title/location LIKE, 기간, 태그 필터 포함 |
| `findUpcoming(Long ownerId, LocalDateTime from, LocalDateTime to)` | 소유자, 기간 | `List<ScheduleTrigger>` | 알림 스캔용. `start_at`이 구간에 속하는 일정 반환 |

### DTO
`ScheduleSummary`
| 필드 | 타입 | 설명 |
|------|------|------|
| id | `Long` | 일정 ID |
| ownerId | `Long` | 소유자 ID |
| title | `String` | 제목 |
| startAt | `LocalDateTime` | 시작 시각 |
| endAt | `LocalDateTime` | 종료 시각 |
| location | `String` (nullable) | 장소 |

`ScheduleSearchQuery`
| 필드 | 타입 | 설명 |
|------|------|------|
| ownerId | `Long` | 검색 범위 사용자 |
| keyword | `String` (nullable) | title/location LIKE 대상 |
| tagIds | `List<Long>` (nullable) | 태그 필터 |

`ScheduleTrigger`
| 필드 | 타입 | 설명 |
|------|------|------|
| id | `Long` | 일정 ID |
| ownerId | `Long` | 소유자 ID |
| title | `String` | 제목 |
| startAt | `LocalDateTime` | 시작 시각 |
| remindBeforeMinutes | `int` | 시작 전 알림 분 |

### Stub 동작
- `findById`: `id == 1L`이면 고정 `ScheduleSummary` 반환, 그 외 `Optional.empty()`
- `existsByIdAndOwner`: `id == 1L && ownerId == 1L`이면 `true`, 그 외 `false`
- `findSummariesByIds`: 입력 리스트 중 `id == 1L`인 것만 고정 샘플 1건 반환
- `search`: 빈 리스트 반환 (검색은 실구현 교체 전 테스트 통과 우선)
- `findUpcoming`: 빈 리스트 반환 (알림 트리거 없음)
- 프로파일: `@Profile("local")`

## 도메인 이벤트: ResourceDeletedEvent

04의 양방향 의존 해소의 핵심. 공통 모듈에서 정의, Spring `ApplicationEventPublisher`로 발행, `@EventListener`로 구독.

### 필드
| 필드 | 타입 | 설명 |
|------|------|------|
| resourceType | `ResourceType` | `SCHEDULE` 또는 `MEMO` enum |
| resourceId | `Long` | 삭제된 리소스 ID |
| ownerId | `Long` | 삭제된 리소스의 소유자 ID (정리 대상 범위 한정용) |
| occurredAt | `LocalDateTime` | 이벤트 발생 시각 |

`ResourceType` enum (공통 모듈 소유): `SCHEDULE`, `MEMO`.

### 발행 측
- 일정 모듈: `schedule` 삭제 트랜잭션 커밋 후 `ResourceDeletedEvent(SCHEDULE, id, ownerId, now)` 발행
- 메모 모듈: `memo` 삭제 트랜잭션 커밋 후 `ResourceDeletedEvent(MEMO, id, ownerId, now)` 발행

### 구독 측 동작
| 모듈 | 구독 대상 | 동작 |
|------|---------|------|
| 연결 | SCHEDULE, MEMO | 해당 ID가 포함된 `schedule_memo_link` 행 일괄 삭제 |
| 태그 | SCHEDULE | `schedule_tag` 중 해당 schedule_id 행 삭제 |
| 태그 | MEMO | `memo_tag` 중 해당 memo_id 행 삭제 |
| 첨부 | SCHEDULE, MEMO | `(target_type, target_id)` 일치 행 삭제 + 스토리지 파일 삭제 (F011) |
| 알림 | SCHEDULE | 인메모리 트리거 큐에서 해당 일정 제거 |

### Stub 동작
- 공통 모듈이 소유하는 이벤트 타입 자체에는 Stub이 필요 없음 (POJO).
- 일정/메모 모듈의 Stub 구현체는 이벤트를 발행하지 않는다(테스트 격리). 통합 테스트는 실제 구현체로 검증.

## 외부 연동 어댑터 포트
