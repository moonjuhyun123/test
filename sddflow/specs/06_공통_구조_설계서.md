## ApiResponse&lt;T&gt;

모든 HTTP 응답의 최상위 봉투. 성공·실패 구분을 HTTP 상태 코드와 `success` 필드로 이중 명시.

| 필드 | 타입 | 설명 |
|------|------|------|
| success | `boolean` | 성공 여부 (true면 data, false면 error) |
| data | `T` (nullable) | 성공 시 페이로드 제네릭. 실패 시 null |
| error | `ErrorBody` (nullable) | 실패 시 에러 상세. 성공 시 null |
| timestamp | `String` (ISO-8601) | 응답 생성 시각 |

- 정적 팩토리: `ApiResponse.ok(T data)`, `ApiResponse.fail(ErrorBody error)`
- 성공 HTTP 상태: 200 (조회/수정), 201 (생성), 204 (삭제 — body 없이 응답)
- 204일 경우 이 봉투 자체 없이 빈 바디 반환 (관습 존중). 그 외 전부 봉투 사용.

## PagedResponse&lt;T&gt;

목록 조회의 표준 형식. `ApiResponse<PagedResponse<T>>`로 감싸 반환.

| 필드 | 타입 | 설명 |
|------|------|------|
| items | `List<T>` | 현재 페이지 항목 |
| page | `int` | 0-base 현재 페이지 번호 |
| size | `int` | 페이지 크기 |
| totalElements | `long` | 전체 항목 수 |
| totalPages | `int` | 전체 페이지 수 (⌈totalElements/size⌉) |
| hasNext | `boolean` | 다음 페이지 존재 여부 |

- **빈 목록** 규약: `items=[]`, `totalElements=0`, `totalPages=0`, `hasNext=false`. 200 OK, null 대신 빈 리스트.
- **페이징 파라미터** (쿼리스트링): `page` (기본 `0`), `size` (기본 `20`, 최대 `100`), `sort` (선택, `field,asc|desc` 형식)

## 에러 응답 (ErrorBody)

실패 시 `ApiResponse.error`에 들어가는 구조.

| 필드 | 타입 | 설명 |
|------|------|------|
| code | `String` | 에러 코드 (예: `SCHED-4001`) |
| message | `String` | 사용자 표시용 메시지 (한국어) |
| details | `List<FieldError>` (nullable) | 필드 단위 검증 실패 목록. 그 외는 null |
| path | `String` | 요청 URI |

`FieldError`
| 필드 | 타입 | 설명 |
|------|------|------|
| field | `String` | 실패 필드명 |
| reason | `String` | 사유 |

- 메시지는 한국어 고정. 다국어 요구는 01에 없음 (추가 금지).
- 스택트레이스·SQL·파일경로 등 내부 정보는 절대 포함 금지.

## 에러 코드 규칙

### 형식
`{모듈접두사}-{번호}` (대문자, 하이픈 구분)

### 모듈 접두사
| 모듈 | 접두사 | 비고 |
|------|-------|------|
| 공통/권한 | `AUTH` | 인증·인가 전반 |
| 공통/검증 | `COMM` | 입력 검증, 공통 파라미터 |
| 사용자/인증 | `USER` | |
| 일정 | `SCHED` | |
| 메모 | `MEMO` | |
| 연결 | `LINK` | |
| 태그 | `TAG` | |
| 첨부 | `FILE` | |
| 검색 | `SRCH` | |
| 알림 | `NOTI` | |

### 번호 체계
- 4자리, HTTP 상태 기반 앞자리 + 도메인 순번
  - `4000~4099`: 400 Bad Request (입력 검증)
  - `4010~4019`: 401 Unauthorized
  - `4030~4039`: 403 Forbidden
  - `4040~4049`: 404 Not Found
  - `4090~4099`: 409 Conflict
  - `5000~5099`: 500 Internal
- 예:
  - `AUTH-4010`: 토큰 없음/만료 → 401
  - `AUTH-4030`: 역할 불일치 → 403
  - `AUTH-4040`: 리소스 소유자 불일치 → 404 (존재 숨김)
  - `SCHED-4000`: startAt > endAt
  - `SCHED-4040`: 일정을 찾을 수 없음
  - `LINK-4090`: 이미 연결된 일정-메모 (F004 "재연결 무시"에 따라 실제로는 idempotent OK 반환, 충돌 에러는 소유자 불일치 등 다른 케이스에 한정)
  - `FILE-4000`: 파일 확장자/용량/개수 위반

### 권한 네임스페이스 (AUTH-*)
| 코드 | HTTP | 설명 |
|------|------|------|
| `AUTH-4010` | 401 | 미인증 (토큰 없음/만료/시그니처 오류) |
| `AUTH-4030` | 403 | 권한 없음 (역할 불일치) — 현재는 단일 역할이므로 거의 미사용 |
| `AUTH-4040` | 404 | 리소스 소유자 불일치 (존재 숨김 목적) |

## 권한 공통 요소

05 확정값: **Controller `@PreAuthorize` + Service 소유자 비교**. PROJECT_CONTEXT "Simple Role + 소유자 검사" 부합.

| 항목 | 값 |
|------|----|
| 권한 애노테이션 패턴 | `@PreAuthorize("isAuthenticated()")` (모든 보호 Controller 메서드). 역할 종류가 `USER` 1종이므로 hasRole은 실질 미사용, `isAuthenticated()`로 충분. |
| 커스텀 애노테이션 | **추가 없음** — 01/05에 근거 없음. 불필요한 추상화 금지(헌법). |
| 권한 예외 클래스 | `UnauthorizedException`(401, `AUTH-4010`), `ForbiddenException`(403, `AUTH-4030`), `ResourceNotFoundException`(404, `AUTH-4040` 또는 `{MODULE}-4040`) |
| 소유자 검사 위치 | **Service 계층 고정** — 리소스 조회 직후 `owner_id == currentUser.getId()` 비교. 불일치 시 `ResourceNotFoundException`(404) 던짐 (존재 숨김). |
| 공통 검사 헬퍼 | `OwnershipGuard.requireOwner(Long resourceOwnerId, Long currentUserId)` — 불일치 시 `ResourceNotFoundException` 던지는 유틸. Service에서 1줄로 호출. |
| Stub 기본 동작 | `@Profile("local")`: 권한 체크 기본 통과. `CurrentUser` stub이 `id=1L`을 고정 반환 + `@PreAuthorize`는 보안 설정을 `permit-all`로 덮는 `local` 프로파일 Security 설정 사용. 통합 테스트(`@ActiveProfiles("test")`)는 실제 JWT 경로를 탄다. |

### 권한 예외 → HTTP/에러코드 매핑

| 예외 | HTTP | 에러 코드 |
|------|------|----------|
| `UnauthorizedException` | 401 | `AUTH-4010` |
| `ForbiddenException` | 403 | `AUTH-4030` |
| `ResourceNotFoundException` | 404 | `{MODULE}-4040` (기본값) 또는 `AUTH-4040` (소유자 불일치) |

`GlobalExceptionHandler(@RestControllerAdvice)` 단일 진입점에서 위 매핑 수행 + `ApiResponse.fail(ErrorBody)` 반환.

## BaseEntity

모든 JPA 엔티티가 `@MappedSuperclass`로 상속. 03 ERD의 공통 컬럼 규칙을 코드로 고정.

| 필드 | 타입 | 설명 |
|------|------|------|
| id | `Long` | `@Id @GeneratedValue(strategy=IDENTITY)` — H2/MySQL `AUTO_INCREMENT` |
| createdAt | `LocalDateTime` | `@CreatedDate` (Spring Data Auditing) |
| updatedAt | `LocalDateTime` | `@LastModifiedDate` |

- `@EntityListeners(AuditingEntityListener.class)` 공통 적용.
- `@EnableJpaAuditing` 설정은 `common.config`에 배치.
- **조인 테이블(`schedule_tag`, `memo_tag`)은 복합 PK라 BaseEntity 미상속**. `created_at`만 필요한 경우 `@CreatedDate` 직접 선언.
- `created_by`는 03에서 채택하지 않음 (단일 사용자, 불필요). 도입 금지.
- `deleted_at`은 03 Soft delete 없음 결정에 따라 미포함.

## 공용 enum

전 모듈에서 공유되는 enum만. 한 모듈 내부용 enum은 여기 금지.

| enum명 | 값 목록 | 사용 모듈 | 근거 |
|--------|--------|----------|------|
| `UserRole` | `USER` | 사용자/인증, 전 모듈 (권한 애노테이션) | 05 CurrentUser |
| `ResourceType` | `SCHEDULE`, `MEMO` | 일정, 메모, 연결, 태그, 첨부, 알림 (이벤트 구독) | 05 `ResourceDeletedEvent`, 03 `attachment.target_type` |

### 모듈 내부 enum (여기 넣지 말 것 — 참고용)
- `RepeatRule` (`NONE`/`DAILY`/`WEEKLY`/`MONTHLY`) → 일정 모듈 내부
- `LinkOrigin` (`SCHEDULE_TO_MEMO`/`MEMO_TO_SCHEDULE`) → 연결 모듈 내부
- `SearchType` (`ALL`/`SCHEDULE`/`MEMO`) → 검색 모듈 내부 (01 F006)

## 공용 유틸

| 이름 | 역할 |
|------|------|
| `OwnershipGuard` | 소유자 ID 불일치 시 `ResourceNotFoundException` 던지는 정적 헬퍼. 모든 Service에서 소유자 검사 1줄 처리. |
| `PageRequestFactory` | 쿼리스트링 `page/size/sort`를 Spring `Pageable`로 변환 + 최대 size 100 강제. |
| `JsonTime` | `LocalDateTime` ↔ ISO-8601 문자열 상호 변환. Jackson 설정에 등록. |
| `PasswordHasher` | 비밀번호 해시/검증 (Spring Security `BCryptPasswordEncoder`를 감싸는 얇은 Bean). 사용자/인증 모듈만 사용하지만 표준 Bean이므로 공통 설정에서 등록. |

## 공용 설정

| 이름 | 역할 |
|------|------|
| `JpaAuditingConfig` | `@EnableJpaAuditing` + `BaseEntity` 리스너 활성 |
| `JacksonConfig` | `LocalDateTime` ISO-8601 직렬화, snake_case ↔ camelCase 정책: **camelCase 유지** (JSON도 camelCase — Java/TS 양쪽 자연스럽게 매핑) |
| `SecurityConfig` | JWT 필터 체인, `/api/auth/login`·health만 permit, 그 외 `authenticated()`, CORS는 내부망 단일 서버라 동일 오리진 허용만 |
| `LocalSecurityConfig` | `@Profile("local")`: permit-all + Stub `CurrentUser` 주입 (06 §권한 Stub 기본 동작) |
| `GlobalExceptionHandler` | `@RestControllerAdvice`. 표 §권한 예외 → HTTP 매핑 + 나머지 예외는 500 `COMM-5000`로 래핑 |
| `SwaggerConfig` | `@OpenAPIDefinition` 루트 + JWT Security Scheme. 모든 Controller에 Swagger 어노테이션 필수 (헌법) |
| `ApplicationEventConfig` | `ResourceDeletedEvent` 발행을 위한 `@EnableAsync` (비동기 구독) 여부 — 06에서는 **동기 발행**으로 확정 (트랜잭션 커밋 후 `TransactionalEventListener(phase=AFTER_COMMIT)`). F004/F007 즉시 반영 요구 부합. |

## 자체 검증 체크리스트

- [x] `ApiResponse<T>`, `PagedResponse<T>`, `ErrorBody` 모두 제네릭/도메인 타입 사용. `Object`, `Map<String,Object>` 0건.
- [x] 에러 코드 모듈 접두사 9종(AUTH, COMM, USER, SCHED, MEMO, LINK, TAG, FILE, SRCH, NOTI) 확정. 05의 인터페이스 사용 모듈과 일치.
- [x] 권한 체크 위치가 05 확정값과 동일 (Controller `@PreAuthorize` + Service 소유자 비교).
- [x] `UnauthorizedException`, `ForbiddenException`, `ResourceNotFoundException` 3종 + HTTP/코드 매핑 명시.
- [x] Stub 기본 동작 "로컬 통과, 테스트는 실제 경로" 원칙 명시.
- [x] BaseEntity 구조가 03의 공통 컬럼 규칙(id/created_at/updated_at, soft delete 없음)과 일치.
- [x] 공용 enum 2종(`UserRole`, `ResourceType`)만 전역에 배치, 모듈 내부 enum은 제외.
- [x] 한 모듈에서만 쓰는 항목 없음 (PasswordHasher는 사용자/인증만 쓰지만 표준 Security Bean이라 공통 설정에 등록 — 예외 근거 명시).

## 역행 사유 없음
