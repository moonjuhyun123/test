# /session9 — 화면별 상세 명세 + 상태 정의

## 역할
너는 PM이다. 각 화면의 구조, 행위, 상태를 상세하게 정의한다.
이 상태 정의가 프론트 테스트 기준이 된다.

## 입력
1. specs/PROJECT_CONTEXT.md
2. specs/01_요구사항명세서.md
3. specs/07_화면목록.md
4. specs/08_디자인_시스템_명세서.md
5. specs/09_분할계획.md (있으면 읽는다)
6. specs/09_화면_상세_명세서.md (있으면 읽는다 — 이전 세션 결과)

## 시작 전 — 세션 범위 결정

### specs/09_분할계획.md가 없는 경우 (첫 번째 세션)
1. specs/07_화면목록.md에서 전체 화면 수와 도메인별 그룹을 확인한다
2. 화면이 10개 이하 → 분할 없이 이 세션에서 전부 설계
3. 화면이 11개 이상 → 분할 계획을 세운다:
   a. 도메인별로 묶는다 (같은 도메인 화면은 같은 세션에)
   b. 한 세션에 화면 5~10개씩
   c. 분할 계획을 사용자에게 보여주고 확인받는다
   d. 확인 후 specs/09_분할계획.md로 저장한다
   e. 이 세션에서는 첫 번째 묶음만 설계한다

### specs/09_분할계획.md가 있는 경우 (이어서 진행)
1. 분할계획을 읽고 이번 세션에서 설계할 화면을 확인한다
2. specs/09_화면_상세_명세서.md를 읽는다 (이전 세션 결과)
3. 이전 세션의 화면은 참조만 한다. 수정하지 않는다.
4. 이번 세션의 화면을 기존 파일에 이어서 추가한다
5. 분할계획에서 완료된 묶음에 ✅ 표시한다

## 할 일 (화면마다 반복)

### 1. 컴포넌트 배치
- 어떤 공통 컴포넌트가 어디에 배치되는지 (위→아래, 왼→오른 순서)
- 디자인 시스템 명세서의 컴포넌트만 사용한다

### 2. 사용자 행위 목록
- 이 화면에서 사용자가 할 수 있는 모든 행위 (클릭, 입력, 선택, 스크롤 등)
- 각 행위의 결과 (화면 이동, API 호출, 모달 표시 등)

### 3. 상태 정의 (테스트 기준)
모든 화면에 아래 상태를 빠짐없이 정의한다:

| 상태 | 보여줄 것 | 사용할 컴포넌트 |
|------|----------|---------------|
| 로딩 중 | 스켈레톤 / 스피너 | Loading |
| 데이터 있음 | 실제 데이터 표시 | Table, Card 등 |
| 데이터 없음 (빈값) | 안내 문구 + 행동 유도 | EmptyState |
| API 에러 | 에러 안내 + 재시도 | ErrorState |
| 권한 없음 | 접근 불가 안내 | AccessDenied |
| 입력 검증 실패 | 필드별 에러 메시지 | Input (error) |
| 성공 | 토스트 / 이동 | Toast |

해당 화면에 적용되지 않는 상태는 "해당 없음"으로 표시하고 사유를 적는다.

## 출력 형식 (화면마다 반복)
```markdown
## S001: {화면명}

### 컴포넌트 배치
- 상단: SearchInput + Button(검색)
- 중앙: Table (컬럼: ...)
- 하단: Pagination

### 사용자 행위
| 행위 | 대상 | 결과 |
|------|------|------|
| 클릭 | 테이블 행 | 상세 화면 이동 |
| 클릭 | 등록 버튼 | 등록 화면 이동 |
| 입력 | 검색창 | 필터링 |

### 상태 정의
| 상태 | 보여줄 것 | 컴포넌트 |
|------|----------|----------|
| 로딩 | 테이블 스켈레톤 | Loading |
| 데이터 있음 | 목록 + 페이징 | Table, Pagination |
| 빈값 | "등록된 항목이 없습니다" | EmptyState |
| 에러 | "불러오기 실패" + 재시도 | ErrorState |
| 권한 없음 | 해당 없음 (모든 사용자 접근 가능) | — |
```

## 출력 파일
1. specs/09_화면_상세_명세서.md (새로 생성 또는 이어서 추가)
2. specs/09_분할계획.md (화면 11개 이상일 때만 생성. 이미 있으면 완료 표시만 갱신)

## 역행 규칙
- 디자인 시스템에 필요한 컴포넌트가 없으면 "/session8부터 다시 실행하세요" 보고
- 요구사항명세서의 행위가 화면 목록에 반영 안 되어 있으면 "/session7부터 다시 실행하세요" 보고

## 절대 규칙
- 상태 정의를 빼먹지 마라. 이게 테스트 기준이다.
- 디자인 시스템 명세서에 없는 컴포넌트를 사용하지 마라
- "있으면 좋을 것 같은" 행위를 추가하지 마라
