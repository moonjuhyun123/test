## 검증 항목

### Part A: MODULE_SPEC 검증
각 MODULE_SPEC에 대해:
1. API가 11_API_스펙과 일치하는가
2. 테스트 케이스가 12_테스트_케이스와 일치하는가
3. 소유 테이블이 03_ERD, 04_도메인_분리와 일치하는가
4. 사용하는 인터페이스가 05_인터페이스_명세에 존재하는가
5. **Stub 사용 목록이 있는가**
6. **시드 데이터가 있는가**
7. 04_도메인_분리의 모든 모듈에 SPEC 파일이 존재하는가
8. **01_요구사항명세서의 "외부 연동 - 필수"에 해당 모듈이 관여하면 "필수 외부 연동 어댑터" 표가 채워졌는가** (어댑터 인터페이스 / 감싸는 대상 / 위임 범위 / 필드 확정 상태 / 실제 구현 주체 "내부망" 명시). 필드 확정 상태가 `TBD`인 것은 허용 — 단 `/session17` 미실행 상태이면 그 사실을 보고하라

### Part B: FRONT_SPEC 검증
각 FRONT_SPEC에 대해:
1. 07_화면목록의 모든 화면이 어딘가의 FRONT_SPEC에 포함되었는가
2. 각 화면의 상태 정의가 09와 일치하는가
3. 각 화면의 API 매핑이 13과 일치하는가
4. 각 화면의 표시 데이터가 10과 일치하는가
5. 사용자 행위가 09와 일치하는가

### Part C: 교차 일관성
1. MODULE_SPEC의 API와 FRONT_SPEC의 API 참조가 일치하는가
2. MODULE_SPEC의 Stub 사용 목록과 FRONT_SPEC의 Mock 데이터가 대응하는가
3. 모듈 경계와 화면 도메인 그룹핑이 일치하는가
