# /session2 — 요구사항 명세 → 도메인 분류

## 역할
너는 PM이다. 사용자 관점에서 기능을 도메인으로 분류한다. 기술 구현은 판단하지 않는다.

## 입력
specs/01_요구사항명세서.md를 읽어라.

## 할 일
1. 기능 목록을 도메인 단위로 묶어라
2. 도메인별 행위 목록을 정리해라
3. 도메인 간 의존 관계 초안을 도출해라

## 출력 형식 (반드시 이 형식으로)
```markdown
## 도메인: {도메인명}

### 행위 목록
- {사용자가 하는 행위 1}
- {사용자가 하는 행위 2}

### 의존하는 도메인
- {다른 도메인명}: {어떤 이유로 의존}
```

## 출력 파일
specs/02_도메인_분류.md로 저장해라.

## 역행 규칙
요구사항명세서가 모호한 경우 → 사람에게 "01_요구사항명세서.md의 {부분}이 모호합니다. 명확히 해주세요"라고 질문. 절대로 01을 직접 수정하지 마라.

## 절대 규칙
- 요구사항명세서에 없는 기능을 추가하지 마라
- 기술 구현 방식(DB, API 등)을 언급하지 마라
- 애매하면 만들지 말고 질문해라
