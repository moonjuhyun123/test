# /rollback — 모듈 구현 롤백

## 사용법
/rollback {모듈명}

## 역할
너는 Dev다. 지정된 모듈의 구현을 시작하기 전 상태로 되돌린다.

## 전제
`/implement-{모듈명}` 실행 시 Step 0에서 `pre-implement-{모듈명}` 태그가 생성돼 있어야 한다.

## 할 일

### 1. 태그 존재 확인
```bash
git tag -l "pre-implement-{모듈명}"
```
- 태그가 없으면: "pre-implement-{모듈명} 태그가 없습니다. 체크포인트가 생성되지 않은 상태에서는 롤백할 수 없습니다." 출력하고 멈춰라.

### 2. 현재 상태 확인
롤백 전 현재 상태를 보고해라:
```bash
git status
git log --oneline pre-implement-{모듈명}..HEAD
```
- 체크포인트 이후 커밋 수와 변경된 파일 수를 출력

### 3. 사용자 확인
아래 내용을 출력하고 사용자에게 확인받아라:
```
🔄 롤백 대상: {모듈명}
- 되돌릴 지점: pre-implement-{모듈명} ({커밋 해시})
- 삭제될 커밋: {N}개
- 영향받는 파일: {N}개

이 작업은 되돌릴 수 없습니다. 진행할까요?
```

### 4. 롤백 실행
사용자가 확인하면:
```bash
git reset --hard pre-implement-{모듈명}
```

### 5. 결과 보고
```
✅ 롤백 완료: {모듈명} 모듈 구현 전 상태로 복원됨
- 현재 위치: pre-implement-{모듈명} ({커밋 해시})
- 태그 유지: pre-implement-{모듈명} (재구현 시 덮어씀)

다음 단계:
1. SPEC 점검: specs/modules/{모듈명}_SPEC.md에 모호하거나 빠진 부분 확인
2. 새 세션에서: /implement-{모듈명} 재실행
```

## 절대 규칙
- 사용자 확인 없이 `git reset --hard`를 실행하지 마라
- 태그가 없으면 실행하지 마라
- 롤백 후 이 세션에서 바로 구현을 재시작하지 마라. 새 세션에서 하도록 안내해라. (같은 세션은 이미 오염된 맥락을 갖고 있다)
- 다른 모듈의 태그나 코드를 건드리지 마라
