# /session6 — 공용 응답/에러/enum/유틸/설정 설계

## 역할
너는 Architect다. 공통 구조를 설계한다. 도메인 로직은 판단하지 않는다.

## 입력
specs/05_공용_인터페이스_명세.md (특히 "권한 체크 위치" 섹션). specs/PROJECT_CONTEXT.md ("권한 구조"). CLAUDE.md의 기술 스택도 참조.

## 할 일
1. ApiResponse<T>, PagedResponse<T>, 에러 응답 형식 설계
2. 에러 코드 네임스페이스 규칙 설계
3. BaseEntity 구조 설계
4. 공용 enum/유틸/설정 목록 도출
5. **권한 관련 공통 요소 설계** (아래)

## 권한 관련 공통 요소 (필수)

세션5의 "권한 체크 위치"와 PROJECT_CONTEXT의 "권한 모델"에 맞춰 아래를 확정한다.

- **권한 애노테이션 패턴**: 체크 위치가 Controller 애노테이션이면 `@PreAuthorize("hasRole('ADMIN')")` 등 기본 패턴 + 프로젝트 커스텀 애노테이션 여부
- **권한 예외 클래스**: `UnauthorizedException`(401), `ForbiddenException`(403). 공통 예외 서브패키지(세션15 확정)에 배치
- **권한 에러 코드**: 기본 체계
  - `AUTH-401`: 미인증 (토큰 없음/만료)
  - `AUTH-403`: 권한 없음 (역할 불일치)
  - `AUTH-404`: 리소스 소유자/조직 불일치 (존재 자체를 숨기기 위해 404로 반환 권장)
- **Stub 권한 동작**: `@Profile("local")` Stub은 **기본 통과**. 로컬 개발 속도 우선. 통합 테스트는 실제 권한 경로를 탄다. 이 원칙을 문서에 명시.

## 출력 형식
```markdown
## ApiResponse<T>
| 필드 | 타입 | 설명 |

## PagedResponse<T>
| 필드 | 타입 | 설명 |

## 에러 응답
| 필드 | 타입 | 설명 |

## 에러 코드 규칙
- 형식: {모듈접두사}-{번호}
- 권한 네임스페이스: AUTH-401 / AUTH-403 / AUTH-404 (기본값 — 프로젝트 정책에 맞게 조정)

## 권한 공통 요소
| 항목 | 값 |
|------|----|
| 권한 애노테이션 패턴 | {예시 또는 커스텀명} |
| 권한 예외 클래스 | UnauthorizedException, ForbiddenException |
| Stub 기본 동작 | 통과 (로컬), 통합 테스트는 실제 경로 |

## BaseEntity
| 필드 | 타입 | 설명 |

## 공용 enum
| enum명 | 값 목록 | 사용 모듈 |

## 공용 유틸 / 공용 설정
| 이름 | 역할 |
```
