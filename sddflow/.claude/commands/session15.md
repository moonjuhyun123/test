## 역할
너는 Architect다. 프로젝트 전체 코드 규칙을 정리한다.

## 입력
specs/ 폴더 전체. 특히 06_공통_구조_설계서.md, 11_API_스펙.md.

## 할 일
CLAUDE.md의 **법률 섹션(이 프로젝트 전용)**의 코드 규칙을 채워라.
헌법 섹션은 건드리지 마라.

채울 항목:
1. 기술 스택 구체화
2. 패키지 구조 규칙 — **공통 모듈 서브패키지 이름을 반드시 확정할 것** (아래 참조)
3. 코드 컨벤션
4. 에러 코드 체계
5. 통합 디테일 (날짜/페이징/빈 목록 등)
6. 확정 범위 (MVP + 모듈 목록)

8. **권한 체크 규칙** — PROJECT_CONTEXT·세션5·세션6 확정값을 법률에 박기 (아래 템플릿)

## 권한 체크 규칙 템플릿 (필수)

법률 섹션에 아래 하위 섹션을 반드시 포함해라. 값은 PROJECT_CONTEXT·05·06에서 그대로 복사.

```
### 권한 체크 규칙

- 권한 모델: {Simple Role / RBAC 정적 / RBAC 동적 / 계층형 RBAC / RBAC + 소유자·조직 / ABAC}  ← PROJECT_CONTEXT에서 복사
- 체크 위치: {Controller 애노테이션 / Service / AOP / Gateway}  ← specs/05에서 복사
- 역할 검사 패턴: {예: @PreAuthorize("hasRole('ADMIN')")}
- 소유자/조직 검사 위치: Service 계층, 리소스 조회 직후 비교
- Stub 동작: 통과 (로컬 개발), 통합 테스트는 실제 권한 경로
- 권한 에러 코드: AUTH-401 (미인증) / AUTH-403 (권한 없음) / AUTH-404 (소유자·조직 불일치)
- 권한 예외: UnauthorizedException, ForbiddenException ({공통 예외 서브패키지}에 배치)
- 금지: Controller/Service/Repository 중 여러 계층에서 권한 검사 중복
```

비어 있거나 `미확정`이 있으면 사용자에게 질문해서 채워라. 플레이스홀더 남기지 마라.

## 외부 연동 어댑터 규칙 템플릿 (필수)

specs/01_요구사항명세서의 "외부 연동 - 필수" 항목이 하나라도 있으면 법률에 아래 하위 섹션을 반드시 포함해라. 값은 01·05·modules/ 에서 집계.

```
### 외부 연동 어댑터 규칙

- 외부 시스템·SDK는 공통 모듈의 어댑터 인터페이스를 통해서만 접근 (Controller/Service에서 SDK 타입 직접 노출 금지)
- 어댑터 Stub: @Profile("local")에서 고정 응답/로그만 반환
- 실제 구현체: 내부망에서 사람이 붙인다. AI는 Stub만 생성하고 그럴듯한 가짜 구현을 만들지 마라.
- 어댑터 위치: {공통 모듈 서브패키지 — 세션15에서 확정한 이름 사용}
- 필수 어댑터 목록:
  | 어댑터 인터페이스 | 감싸는 대상 | 위임 범위 | 필드 확정 상태 |
  |-----------------|-----------|---------|-------------|
  | {예: SsoAuthPort} | {예: 사내 SSO} | {예: 인증만} | {TBD / 17_외부연동_확인리스트에서 확정} |
```

필수 연동이 없는 프로젝트면 이 섹션 자체를 생략해도 된다 (섹션이 있으면 표가 비어선 안 됨).

## 패키지 구조 확정 (필수)

공통 모듈의 서브패키지 이름을 여기서 확정한다. 이후 모든 `/build-*`와 `/implement-*`가 이 값만 따른다.

CLAUDE.md 헌법 "네이밍 금지 목록"의 Java 예약어는 **빈 디렉토리로라도 금지**. 아래 서브패키지마다 권장 대안 중 하나를 선택해 법률에 박아라.

```
### 패키지 구조

- 기본: {com.company.project}
- 공통: {com.company.project.common}
- 공통 모듈 서브패키지:
  - 공용 인터페이스: {api | contract | port 중 택1}          ← interface 금지
  - 공용 enum:      {type | code | constant 중 택1}         ← enum 금지
  - 공용 DTO:       {dto}
  - 공용 유틸:      {util}                                  ← static 금지
  - 공용 설정:      {config}
  - 공용 예외:      {exception | error 중 택1}
  - Stub 구현체:    {stub}  (@Profile("local"))
  - BaseEntity:     {entity | domain 중 택1}
- 도메인 모듈 서브패키지: {controller, service, repository, entity, dto}
```

사용자가 선호 이름을 명시적으로 주지 않았다면 위 권장 대안 중 **첫 번째**를 기본값으로 선택한다 (인터페이스 → `api`, enum → `type`, 예외 → `exception`, BaseEntity → `entity`). 다른 이름을 원하면 사용자에게 확인해라.

확정 후 법률의 "패키지 구조" 섹션에 **모든 서브패키지 이름을 명시**해라. 빈 항목을 남기지 마라.
