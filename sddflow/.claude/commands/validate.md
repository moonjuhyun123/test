# /validate — 명세 정합성 검증

## 역할
너는 QA다. 산출물 간 누락과 불일치를 찾는다.

## 입력
specs/ 폴더 전체를 읽어라.

## 할 일
아래 항목을 전부 검증하고 결과를 보고해라:

### 1. API ↔ MODULE_SPEC 정합성
- [ ] API 스펙(11)의 모든 엔드포인트가 MODULE_SPEC에 존재하는가
- [ ] MODULE_SPEC의 모든 엔드포인트가 API 스펙(11)에 존재하는가

### 2. API ↔ 테스트 케이스 정합성
- [ ] API 스펙(11)의 모든 엔드포인트에 테스트 케이스(12)가 있는가
- [ ] 모든 API에 최소 성공/실패/권한 케이스가 있는가

### 3. ERD ↔ API 정합성
- [ ] API가 참조하는 모든 필드가 ERD에 존재하는가
- [ ] ERD에 있는데 어떤 API에서도 사용하지 않는 테이블이 있는가

### 4. 인터페이스 ↔ MODULE_SPEC 정합성
- [ ] MODULE_SPEC에서 사용하는 인터페이스가 공용 인터페이스 명세(05)에 존재하는가
- [ ] 공용 인터페이스 명세에 있는데 어떤 모듈에서도 사용하지 않는 인터페이스가 있는가

### 5. Stub ↔ 모듈 정합성
- [ ] 모든 MODULE_SPEC에 Stub 사용 목록이 있는가
- [ ] 모든 MODULE_SPEC에 시드 데이터가 있는가

### 6. ★ 표시 데이터 ↔ API 정합성
- [ ] 표시_데이터_명세(10)의 모든 데이터 항목이 API 스펙(11) 응답으로 커버되는가
- [ ] 표시_데이터_명세(10)의 모든 입력 항목이 API 스펙(11) 요청에 포함되는가
- [ ] 커버 안 되는 데이터 항목 목록

### 7. ★ 화면-API 매핑 ↔ API 정합성
- [ ] 화면_API_매핑(13)에 매핑된 모든 API가 API 스펙(11)에 존재하는가
- [ ] API 스펙(11)의 모든 엔드포인트가 최소 1개 화면에 매핑되었는가

### 8. ★ FRONT_SPEC ↔ MODULE_SPEC 일관성
- [ ] FRONT_SPEC의 API 참조가 MODULE_SPEC의 API 엔드포인트와 일치하는가
- [ ] FRONT_SPEC의 Mock 데이터와 MODULE_SPEC의 Stub 사용이 대응하는가

### 9. ★ 화면목록 ↔ FRONT_SPEC 완전성
- [ ] 화면목록(07)의 모든 화면이 FRONT_SPEC에 배정되었는가
- [ ] FRONT_SPEC의 상태 정의가 화면_상세(09)와 일치하는가

### 10. ★ 화면_상세 ↔ 표시_데이터 완전성
- [ ] 화면_상세(09)의 모든 컴포넌트에 대응하는 표시 데이터가 10에 정의되었는가

## 출력 형식
```
✅ {검증 항목}: 통과
❌ {검증 항목}: {구체적 누락/불일치 내용}
⚠️ {검증 항목}: {경고 — 문제는 아니지만 확인 필요}
```

## 출력
터미널에 결과를 출력해라. 파일로 저장하지 마라.

## 절대 규칙
- 검증만 해라. 수정하지 마라.
- 누락을 발견해도 스스로 채우지 마라. 보고만 해라.
