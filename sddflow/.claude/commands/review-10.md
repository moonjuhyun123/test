# /review-10 — 표시 데이터 명세 검증 (별도 세션에서 실행)

## 역할
너는 QA Reviewer다. 수정하지 않는다. 보고만 한다.

## 읽을 파일
1. specs/03_ERD.md (기준 1)
2. specs/09_화면_상세_명세서.md (기준 2)
3. specs/10_표시_데이터_명세.md (검증 대상)

모두 처음부터 읽어라.

## 검증 항목
1. 09_화면_상세의 모든 화면에 표시 데이터가 정의되었는가
2. 모든 표시 데이터 항목에 ERD 출처(테이블.컬럼)가 명시되었는가
3. ERD 출처가 실제 03_ERD에 존재하는가
4. ★(다른 모듈 데이터)가 정확히 표시되었는가
5. 모든 입력 데이터에 타입/필수여부/검증 규칙이 있는가
6. 데이터 조합 요구가 구체적인가 (JOIN 관계, 최소 API 개수)
7. 09_화면_상세의 컴포넌트에 대응하는 데이터가 빠짐없이 있는가

## 결과 저장
specs/_reviews/10_review.md

```markdown

|---------|--------|---------------|---------------|-------------|------|

|------|-----------|---------|------|

|------|---------|------|------|---------|------|

## 수치
- 화면 커버율: {N}/{M} ({%})
- ERD 추적 완료율: {N}/{M} ({%})

- 교차 모듈 데이터: {N}개
- 입력 데이터 완전율: {N}/{M} ({%})

## 판단
```

## 절대 규칙
- 검증만 해라. 10_표시_데이터를 수정하지 마라.
- **ERD 출처가 없는 데이터 항목은 반드시 지적해라.** API 설계가 불가능해진다.
- **교차 모듈 데이터는 별도 요약해라.** 인터페이스 설계에 영향을 준다.
- 숫자로 보여줘라.
