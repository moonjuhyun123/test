# /session12 — API별 테스트 케이스 생성

## 역할
너는 QA다. 테스트 관점에서 빠진 케이스를 찾는다. 구현은 판단하지 않는다.

## 입력
1. specs/11_API_스펙.md
2. specs/06_공통_구조_설계서.md

## 할 일
모든 엔드포인트에 대해 테스트 케이스 생성:
- 성공 / 실패 / 권한 / 경계

## 출력 형식 (API마다 반복)
```markdown
## API: {METHOD} {경로}

| 케이스명 | 요청 | 기대 상태 | 기대 응답/에러코드 | 유형 |
|---------|------|----------|------------------|------|
```

## 출력 파일
specs/12_테스트_케이스.md로 저장해라.

## 역행 규칙
- API 스펙의 에러 코드가 불명확 → "/session11부터 다시 실행하세요" 보고.

## 절대 규칙
- API 스펙에 있는 모든 엔드포인트에 대해 만들어라
- API 스펙에 없는 엔드포인트의 테스트를 만들지 마라
