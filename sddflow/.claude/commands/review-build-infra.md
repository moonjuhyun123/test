# /review-build-infra — 유틸/설정/테스트 검증 (별도 세션에서 실행)

## 역할
너는 QA Reviewer다. 수정하지 않는다. 보고만 한다.

## 전제
/build-skeleton + /build-interfaces + /build-infra가 완료됐다고 보고된 상태여야 한다.
이 리뷰가 통과하면 공통 모듈이 완성된 것이고, 구현 단계(/implement-{모듈})로 넘어갈 수 있다.

## 읽을 파일
1. specs/06_공통_구조_설계서.md (기준)
2. src/{common-module}/ 전체 (검증 대상 — skeleton/interfaces 산출물 포함 전체)

## 검증 항목

### 1. 유틸 커버율
- 06의 유틸 목록과 생성된 유틸 코드 대조 (누락/추가 목록)
- 날짜/시간 변환, 페이징 처리, 검색 조건 빌더, 파일 검증 등 06에 명시된 것

### 2. 필수 설정
- GlobalExceptionHandler 존재 + 에러 응답 형식이 06과 일치
- CORS 설정 존재
- 06에 명시된 필터/인터셉터 존재

### 3. 테스트 베이스 클래스
- BaseIntegrationTest 존재: @SpringBootTest, @ActiveProfiles("local"), MockMvc 주입
- BaseUnitTest 존재

### 4. 공통 모듈 테스트 커버 (테스트 코드 존재 여부)
- ApiResponse 직렬화/역직렬화 테스트
- PagedResponse 페이징 정보 테스트
- GlobalExceptionHandler 에러 응답 형식 테스트
- 각 Stub 동작 테스트 (/build-interfaces에서 만든 모든 Stub)
- BaseEntity auditing 테스트
- 공용 유틸 테스트 (유틸별 1개 이상)

### 5. 빌드 + 테스트 실행
- 공통 모듈 빌드 실행 → 통과 여부
- **공통 모듈 테스트 전체 실행 → 통과 수 / 총 수 / 실패 목록**
- 빈 도메인 모듈 + 공통 모듈 의존 빌드 실행 → 통과 여부
- 실행이 불가능한 환경이면 "실행 불가"로 명시하고 그 경우 판단은 ❌

### 6. 추가 금지 (역행 검증)
- 06에 없는 "있으면 좋을 것 같은" 유틸이 추가돼있는가
- 06에 없는 설정이 추가돼있는가

### 7. 네이밍 위반 검증 (정적 스캔 — 빌드/테스트 통과와 무관)
- 공통 모듈 전체(skeleton + interfaces + infra 산출물)의 .java 파일 `package` 선언과 디렉토리 경로 스캔
- CLAUDE.md 헌법 "네이밍 금지 목록"의 Java 예약어와 대조
- **세션 12 마지막 관문이니 여기서 놓치면 도메인 구현 세션에서 터진다.** 꼼꼼히 해라
- 이 단계에서 주의할 실수:
  - `common.static/` (유틸) — `static`은 Java 예약어
  - `common.default/` — `default`는 Java 예약어
  - interfaces 단계의 `common.interface`/`common.enum`이 아직 남아있는 경우
- 위반 건 + 영향받는 import 체인 함께 보고
- CLAUDE.md 법률 "패키지 구조"의 모든 서브패키지 값이 코드와 일치하는지 최종 확인

## 절대 규칙
- 검증만 해라. 코드를 수정하지 마라.
- **테스트는 반드시 실행해라.** "테스트 코드가 있다"는 통과가 아니다. "테스트가 전부 통과한다"가 통과다.
- 실행이 불가능한 환경이면 "실행 불가"로 명시하고 판단은 ❌다.
- 06에 없는 유틸/설정을 발견하면 반드시 무단 추가 섹션에 보고해라.
- 한 개라도 테스트가 실패하면 판단은 ❌다.
- **네이밍 위반 1건이라도 있으면 판단은 ❌다.** 빌드/테스트 통과와 무관. 세션 12 마지막 관문이니 여기서 통과시켜선 안 된다.
