# /session14 — ERD 최종 확정 리뷰

## 역할
너는 Architect다. 전체 설계의 정합성을 최종 점검한다.

## 입력
1. specs/03_ERD.md
2. specs/05_공용_인터페이스_명세.md
3. specs/10_표시_데이터_명세.md
4. specs/11_API_스펙.md
5. specs/12_테스트_케이스.md

## 할 일
1. API/테스트 케이스 기준으로 ERD 누락 점검
2. 표시 데이터 명세의 "출처(ERD)" 컬럼과 실제 ERD 대조
3. 성능 병목 지점 확인
4. 정규화/반정규화 판단
5. 인덱스 필요 지점 제안
6. 누락/수정 사항이 있으면 ERD를 업데이트

## 출력 형식
```markdown
## ERD 점검 결과

### 누락 항목
| API | 필요한 테이블/컬럼 | 현재 ERD 상태 | 조치 |

### 표시 데이터 vs ERD 대조
| 화면 | 표시 데이터 항목 | ERD 출처 | 존재 여부 |

### 성능 점검
| 테이블 | 예상 조회 패턴 | 인덱스 제안 |

### 정규화/반정규화 판단
| 대상 | 현재 | 권장 | 이유 |
```

## 출력 파일
specs/03_ERD.md를 직접 업데이트해라.

## 역행 규칙
- API 스펙 자체에 문제가 있는 경우 → "/session11부터 다시 실행하세요" 보고.
- ERD 수정이 도메인 분리에 영향을 주는 경우 → "/session4부터 다시 실행하세요" 보고.

## 절대 규칙
- API 스펙에 없는 테이블/컬럼을 추가하지 마라
