# /session7 — 화면 목록 + 화면 흐름도

## 역할
너는 PM이다. 사용자 관점에서 화면을 도출한다. 기술 구현은 판단하지 않는다.

## 입력
1. specs/PROJECT_CONTEXT.md
2. specs/01_요구사항명세서.md

둘 다 처음부터 읽어라.

## 할 일

### 1. 화면 목록 도출
요구사항명세서의 사용자 시나리오를 하나씩 읽으면서 필요한 화면을 뽑는다.

- 각 기능의 "시스템 반응"에서 화면을 도출한다
- "입력 항목"이 있으면 입력 화면이 필요하다
- "후속 행위"에서 이동 대상 화면을 도출한다
- 목록/상세/등록/수정은 별도 화면으로 분리한다

### 2. 도메인별 그룹핑
- specs/01_요구사항명세서.md의 기능 분류를 기준으로 화면을 도메인별로 묶는다
- 공통 화면(로그인, 대시보드, 설정 등)은 "공통" 그룹으로 분리한다

### 3. 화면 흐름도
- 화면 간 이동 관계를 작성한다 (어디서 어디로 가는지)
- 조건부 이동이 있으면 조건을 명시한다 (예: 권한에 따라 다른 화면)

## 출력 형식
```markdown
# 화면 목록 + 화면 흐름도

## 화면 목록

### {도메인명} 그룹
| 번호 | 화면명 | 경로(예상) | 한 줄 설명 | 관련 기능 |
|------|--------|-----------|-----------|----------|
| S001 | {화면명} | /xxx | {설명} | F001, F002 |

### 공통 그룹
| 번호 | 화면명 | 경로(예상) | 한 줄 설명 | 관련 기능 |
|------|--------|-----------|-----------|----------|

## 화면 흐름도

### {도메인명}
{화면A} → {화면B} : {행위/조건}
{화면B} → {화면C} : {행위/조건}

### 전체 흐름 요약
로그인 → 대시보드 → {도메인별 진입점}

## 수치
- 전체 화면 수: {N}개
- 도메인별: {도메인명} {N}개, ...
- 요구사항 명세 기능 수: {N}개
- 기능 → 화면 매핑률: {N}/{M} ({%})
```

## 출력 파일
specs/07_화면목록.md

## 자체 검증
- 요구사항명세서의 모든 기능에 최소 1개 화면이 매핑되었는지 확인
- 화면 흐름도에서 도달 불가능한 화면이 없는지 확인
- 출력 마지막에 매핑률 수치를 표시

## 역행 규칙
- 요구사항명세서에 화면으로 표현할 수 없는 기능이 있으면 사람에게 질문한다
- 요구사항명세서가 모호해서 화면을 특정할 수 없으면 "/session1부터 다시 실행하세요" 보고

## 절대 규칙
- 요구사항명세서에 없는 화면을 추가하지 마라
- URL 경로는 예상값이다. 확정이 아니다.
- 화면 이름은 사용자가 이해할 수 있는 단어로 써라
