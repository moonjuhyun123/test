# 요구사항 명세 수집 질문 체크리스트

## 사용 방법

사용자(실제 업무 담당자)와 인터뷰할 때 이 순서대로 질문한다.
기술 용어 쓰지 않는다. 사용자의 말 그대로 기록한다.

---

## 1단계: 하루 흐름 파악

> 목적: 행위를 빠짐없이 수집

- [ ] "출근해서 이 시스템에 제일 먼저 뭘 하세요?"
- [ ] "그 다음에는요?" (더 이상 안 나올 때까지 반복)
- [ ] "퇴근 전에 마지막으로 하는 건 뭐예요?"
- [ ] "매일 하는 건 뭐고, 가끔 하는 건 뭐예요?"
- [ ] "매주/매월 한 번씩 하는 일이 있으세요?"
- [ ] "급하게 처리해야 할 때 이 시스템에서 뭘 하세요?"

---

## 2단계: 역할별 흐름 파악

> 목적: 사용자 유형과 권한 구분

- [ ] "이 시스템 쓰는 사람이 몇 종류예요?" (일반 사용자 / 관리자 / 부서장 등)
- [ ] "각각 할 수 있는 게 다른가요? 뭐가 달라요?"
- [ ] "다른 사람이 한 걸 확인하거나 승인하는 일이 있나요?"
- [ ] "신입이 처음 이 시스템 쓸 때 뭐부터 해요?"

---

## 3단계: 행위별 상세 파고들기

> 목적: 각 행위를 시나리오로 전환. 수집된 행위마다 반복.

- [ ] "그거 하려면 먼저 뭐가 되어 있어야 해요?" (전제 조건)
- [ ] "그거 하면 화면에 뭐가 나와요?" (시스템 반응)
- [ ] "그거 하고 나면 끝이에요? 다음에 뭐가 이어져요?" (후속 행위)
- [ ] "그거 잘못하면 어떻게 돼요? 되돌릴 수 있어요?" (예외/복구)
- [ ] "그거 할 때 뭘 입력해요? 뭘 선택해요?" (입력 항목)
- [ ] "그거 끝나면 누구한테 알려줘야 해요?" (알림/연동 지점)

---

## 4단계: 교차 지점 파악

> 목적: 모듈 간 의존 관계 도출

- [ ] "이거 하면 다른 사람한테 뭐가 가나요?" (알림, 승인 요청 등)
- [ ] "다른 사람이 한 걸 받아서 처리하는 일이 있나요?"
- [ ] "파일 첨부하는 곳이 어디어디예요?"
- [ ] "같은 정보를 여러 곳에서 보는 경우가 있나요?"

---

## 5단계: 불편사항 + 우선순위

> 목적: 개선 포인트 수집 + MVP 판단 기준

- [ ] "지금 제일 짜증나는 게 뭐예요?"
- [ ] "이거 안 되면 어떻게 하세요?" (행위마다)
  - "전화해요 / 엑셀로 해요" → 후순위
  - "업무가 멈춰요" → 필수
- [ ] "있으면 좋겠는데 지금은 없는 기능이 있나요?"
- [ ] "안 쓰는 기능이 있나요? 왜 안 쓰세요?"
- [ ] "이것만 되면 일단 쓸 수 있다, 하는 게 뭐예요?" (MVP 핵심)

---

## 6단계: 환경/제약 파악

> 목적: 기술 스택 및 운영 환경 결정 입력

- [ ] "주로 PC에서 쓰세요? 모바일에서도 쓰나요?"
- [ ] "동시에 몇 명 정도 쓰나요?"
- [ ] "외부에서 접속하는 경우가 있나요?"
- [ ] "다른 시스템이랑 연결되는 게 있나요?" (인사DB, 메일, 결재 등)
- [ ] "보안 관련해서 지켜야 하는 규칙이 있나요?"

---

## 인터뷰 팁

- **"기능"을 묻지 말고 "행동"을 물어라.** "어떤 기능이 필요하세요?"는 안 된다. "뭘 하세요?"가 맞다.
- **사용자가 말한 단어 그대로 적어라.** 개발 용어로 번역하지 않는다. 번역은 정리할 때 한다.
- **시연을 부탁해라.** "보여주실 수 있어요?"가 가장 정확하다. 화면 공유나 옆에서 보기.
- **침묵을 견뎌라.** 질문 후 바로 답 안 나와도 기다린다. 5초 후에 진짜 중요한 게 나온다.
- **직급별로 따로 인터뷰해라.** 같이 하면 아래 사람이 말을 못 한다.
