# /session1-self — 요구사항명세서 작성 (사용자 초안 기반)

## 용도
사용자가 이미 요구사항을 머릿속이나 초안으로 정리해 둔 경우, 인터뷰(`/session1`)를 생략하고 **초안을 `specs/01_요구사항명세서.md` 표준 틀에 맞춰 정규화**하는 명령어.

`/session1`과 산출물 파일·형식·자체 검증 기준은 **완전히 동일**하다. 다음 세션(`/session2` 등)은 입력이 같으므로 아무 영향 받지 않는다.

## 역할
너는 PM이다. 사용자가 제공한 초안을 읽고, **내용은 임의로 추가/해석하지 말고** 표준 틀에 재배치한다. 부족한 항목은 사용자에게 **짧게 되물어** 채운다.

---

## 입력 받기

사용자에게 다음 중 하나를 요청한다:
1. 초안 파일 경로 (예: `specs/01_요구사항명세서_draft.md`, 메모장 파일 등)
2. 채팅에 초안 본문 붙여넣기
3. 기존에 `specs/01_요구사항명세서.md`가 있으면 그것을 초안으로 간주

초안이 없으면 "`/session1-self`는 초안이 필요합니다. 초안 없이 처음부터 작성하려면 `/session1`을 쓰세요."라고 안내하고 중단한다.

---

## 처리 순서

### Step 1: 초안 읽고 분류

초안 내용을 아래 슬롯에 매핑한다. 원문 표현을 최대한 보존하고, 개발 용어로 **번역하지 않는다**.

- 프로젝트 개요 (프로젝트명, 한 줄 설명, 유형)
- 사용자 유형 (역할/권한)
- 기능 목록 (행위 단위)
- 기능별 상세 (시나리오, 전제조건, 입력, 반응, 후속, 예외, 알림, **외부 연동**)
- **외부 연동** — 시스템 이름·용도·필수/선택만. 입력/출력 필드·담당자·계약 자료는 수집하지 마라. 초안에 있어도 `외부 의존 최소화 원칙`에 따라 재해석 (예: "SSO에서 이름·부서 가져옴" → "SSO는 인증만, 프로필은 내부 DB"). 필드는 설계 후 `/session17`이 역산
- MVP 분류 (필수 / 후순위)
- 환경/제약 (접속, 동시 사용자, 외부, 연동, 보안)
- 기술 스택

### Step 2: 결손 식별 + 짧은 질문

슬롯별로 초안에서 **누락되거나 애매한** 항목만 골라, **한 번에 묶어** 사용자에게 질문한다. 6단계 인터뷰를 처음부터 다시 하지 마라.

질문 형식 예시:
```
초안을 정리했는데, 아래 항목이 비어 있거나 애매합니다:
1. 사용자 유형: "관리자"와 "일반"이 각각 할 수 있는 일이 달라 보이는데, 구체적으로 뭐가 다른가요?
2. F003(승인 처리)의 예외: 반려하면 어떻게 되나요? 되돌릴 수 있나요?
3. 동시 사용자 수: 초안에 없습니다. 대략 몇 명인가요?
4. 기술 스택(프론트): 비어 있습니다. 확정된 게 있나요, 아직 미확정인가요?
```

사용자가 "모름/미확정"이라고 답하면 해당 슬롯은 `미확정`으로 기록한다. 억지로 채우지 마라.

### Step 3: 표준 틀로 출력

아래 출력 형식에 맞춰 `specs/01_요구사항명세서.md`로 저장한다. 형식은 `/session1`과 동일하다.

## 출력 파일
`specs/01_요구사항명세서.md`로 저장한다. 기존 파일이 있으면 덮어쓰기 전에 사용자에게 확인한다.

## 자체 검증
- 초안에서 추출한 행위 수와 기능 목록 수가 일치하는지 확인
- MVP 필수/후순위 분류가 초안 표현과 일치하는지 확인 ("업무 멈춤" → 필수, "전화/엑셀로 대체" → 후순위)
- **PROJECT_CONTEXT의 권한 모델이 "RBAC 동적"이면 기능 목록에 "역할 관리", "권한 할당", "사용자-역할 매핑" 기능이 있는지 확인.** 없으면 사용자에게 "관리자가 역할을 동적으로 만들려면 이 기능이 필요한데 포함할까요?" 질문.
- 출력 마지막에 한 줄:
  `초안 행위 {N}개 → 기능 {N}개 작성, MVP 필수 {N}개 / 후순위 {N}개, 결손 슬롯 {N}개 보완 완료`

## 절대 규칙
- **초안에 없는 기능을 추가하지 마라.** 애매하면 사용자에게 질문해서 확정한 뒤 기록한다.
- **사용자 표현을 개발 용어로 번역하지 마라.** 초안이 "결재 올린다"면 "승인 요청 생성"으로 바꾸지 말고 "결재 올린다"로 기록한다.
- **미확정은 `미확정`으로 남겨라.** 그럴듯하게 채우지 마라.
- **6단계 인터뷰를 처음부터 다시 하지 마라.** 결손 슬롯만 묶어서 한 번에 묻는다.
- 다음 세션(`/review-01`, `/session2`)이 이 파일을 그대로 입력으로 쓰므로, 형식·키 이름·표 컬럼 구조는 `/session1` 산출물과 **바이트 단위로 호환**이 되도록 유지한다.
